# Maxima Pridex Task Mentions

**Русский** · [English](README.en.md)

Бесплатный локальный модуль для **коробочного Битрикс24**. Когда сотрудника упоминают через `@` в **чате задачи**, модуль пытается автоматически добавить его в **соисполнители** (по умолчанию) или **наблюдатели**.

> Это исходный код, а не приложение Маркетплейса Битрикс24. Установка и обновление выполняются вручную; установка на конкретной версии портала не гарантируется. До применения на рабочем портале проверьте модуль на тестовой задаче.

## Как это работает

- Использует PHP-событие `im:OnAfterMessagesAdd` и обрабатывает только чаты задач (`TASKS_TASK`).
- Извлекает упомянутых пользователей из BB-кода вида `[USER=123]Имя[/USER]`.
- Изменяет задачу **с правами автора сообщения**, без обхода прав Битрикс24. Если автор не вправе изменить участников, добавление не выполняется.
- Не дублирует уже существующих участников, не меняет их роли, не добавляет автора сообщения или неактивных пользователей.
- Не затрагивает другие чаты, старые форумные комментарии и системные сообщения.
- Режим выбирается в настройках модуля: **соисполнители (0)** или **наблюдатели (1)**. Значение сохраняется в БД портала.

## Установка (стандартная BitrixVM, Linux)

Ниже показаны стандартные пути BitrixVM. Предполагается, что корень сайта — `/home/bitrix/www`, пользователь сайта — `bitrix`, а репозиторий `avmaksimov/bitrix-task-mentions` уже опубликован на GitHub с веткой `main`.

### 1. Скачать и распаковать

Подключитесь к серверу по SSH. Команды можно выполнять от `root` (или с доступом к `sudo`):

```bash
curl -fL --retry 2 -o /tmp/bitrix-task-mentions.tar.gz \
  https://github.com/avmaksimov/bitrix-task-mentions/archive/refs/heads/main.tar.gz

sudo install -d -o bitrix -g bitrix -m 755 \
  /home/bitrix/www/local /home/bitrix/www/local/modules

sudo tar -xzf /tmp/bitrix-task-mentions.tar.gz \
  -C /home/bitrix/www --strip-components=1 \
  bitrix-task-mentions-main/local/modules/maximapridex.taskmentions
```

Архив репозитория скачивается целиком во временный файл `/tmp/bitrix-task-mentions.tar.gz`, но команда `tar` извлекает **только каталог модуля**. README, лицензия и прочие файлы репозитория в корень сайта не копируются.

Каталог модуля должен получиться таким:

`/home/bitrix/www/local/modules/maximapridex.taskmentions/`

Назначьте правильного владельца и права, **особенно если распаковывали от `root`**:

```bash
sudo chown -R bitrix:bitrix /home/bitrix/www/local/modules/maximapridex.taskmentions
sudo find /home/bitrix/www/local/modules/maximapridex.taskmentions -type d -exec chmod 755 {} +
sudo find /home/bitrix/www/local/modules/maximapridex.taskmentions -type f -exec chmod 644 {} +
```

Права: папки `755`, обычные файлы `644`. Не используйте `777`. Содержимое `/local/` — часть сайта Битрикс24, а не каталог в корне Linux.

### 2. Проверить защиту `/local/` в nginx

`/local/` расположен в веб-корне. PHP-файлы модуля не должны быть доступны для прямых HTTP-запросов. У модуля есть `.htaccess` для Apache и проверка `B_PROLOG_INCLUDED`, но **nginx не читает `.htaccess`**.

Подставьте адрес **своего** портала вместо `portal.example.com`:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://portal.example.com/local/
curl -sS -o /dev/null -w '%{http_code}\n' https://portal.example.com/local/modules/maximapridex.taskmentions/include.php
```

Ожидается `403` в обоих случаях. Если это так и вы убедились, что запрет задан именно для этого виртуального хоста nginx, переходите к шагу 3. Один код `403` не доказывает, что ответ отдал именно nginx: проверьте конфигурацию при сомнениях.

**Если доступ не закрыт:** в стандартной BitrixVM можно создать отдельный файл конфигурации. Сначала убедитесь, что нужный HTTPS-сервер подключает каталог `site_settings/default`:

```bash
sudo grep -nF 'include bx/site_settings/default/*.conf' /etc/nginx/bx/site_enabled/ssl.s1.conf
```

Если файла или подключения нет, либо конфигурация отличается, **не выполняйте следующие команды вслепую** — обратитесь к администратору сервера. Не закрывайте весь `/local/`, если в нём уже есть необходимые браузеру JS/CSS, изображения или AJAX-обработчики; такие ресурсы потребуют отдельных разрешающих правил.

Проверьте, не существует ли уже файл `/etc/nginx/bx/site_settings/default/local_security.conf`. **Не перезаписывайте существующий файл**, сначала изучите его. Если файла нет, создайте:

```bash
sudo tee /etc/nginx/bx/site_settings/default/local_security.conf > /dev/null <<'EOF'
# Deny direct HTTP access to /local
location = /local {
    return 403;
}

location ^~ /local/ {
    return 403;
}
EOF

sudo chown root:root /etc/nginx/bx/site_settings/default/local_security.conf
sudo chmod 644 /etc/nginx/bx/site_settings/default/local_security.conf
sudo nginx -t
```

**Если `nginx -t` сообщает об ошибке:** не перезагружайте nginx. Если вы *только что создали* этот файл и ранее его не было, удалите его:

```bash
sudo rm /etc/nginx/bx/site_settings/default/local_security.conf
sudo nginx -t
```

Дальнейшую настройку поручите администратору сервера.

**Если `nginx -t` успешен:** примените конфигурацию и повторите оба HTTP-запроса из начала шага 2:

```bash
sudo systemctl reload nginx
```

Ожидается `403` и для каталога, и для PHP-файла. Если результат отличается, попросите администратора проверить виртуальный хост и приоритет правил `location`. Не закрывайте весь `/local/` без учёта потребностей других модулей.

### 3. Установить модуль в Битрикс24

Войдите на портал с правами администратора. В интерфейсе коробочного Битрикс24 откройте **Маркетплейс → меню (⋯/«Ещё») → Установить** и установите модуль **Maxima Pridex: участники задач по упоминанию**. Названия пунктов могут немного отличаться в зависимости от версии портала.

Копирование файлов на сервер само по себе не регистрирует обработчик событий: установку в портале нужно выполнить **один раз**.

### 4. Выбрать роль и проверить

Откройте **Настройки → Настройки продукта → Настройки модулей**, выберите модуль или перейдите напрямую (подставьте домен своего портала):

`https://portal.example.com/bitrix/admin/settings.php?mid=maximapridex.taskmentions&lang=ru`

Выберите, куда добавлять упомянутых: **Соисполнители** (по умолчанию) или **Наблюдатели**. Сохраните настройку. В тестовой задаче упомяните сотрудника через `@` и проверьте, что он добавился. Проверьте также упоминание от исполнителя: добавление зависит от прав **автора сообщения**, а не только постановщика задачи.

## Обновление вручную

1. Посмотрите изменения в репозитории и выберите подходящий момент для обновления.
2. Повторите команды из **шага 1**: скачайте актуальный архив, распакуйте и назначьте права. Существующие файлы с теми же именами будут заменены. Если в новой версии удалили какие-то файлы, старые файлы нужно удалить вручную после проверки изменений — команда распаковки их не удаляет.
3. Модуль уже зарегистрирован в портале; повторно устанавливать его **не требуется**. Настройки, сохранённые в БД, сохраняются.
4. При необходимости очистите PHP OPcache или перезапустите PHP-процессы штатным способом, затем повторите тест с `@`.

**Обновления выполняются вручную.** Перед обновлением проверяйте изменения и источник архива; используйте доверенный публичный репозиторий.

## Удаление

Сначала удалите модуль через интерфейс Битрикс24, чтобы отключить обработчик событий. Затем, если нужно, удалите `/home/bitrix/www/local/modules/maximapridex.taskmentions/`. Добавленные ранее участники останутся в задачах. Настройки nginx для `/local/` при удалении модуля **не удаляйте**: они относятся к защите всего портала.

## Ограничения

Доступность события и формат полей чата зависят от версии коробки. Одновременные изменения участников задачи могут конфликтовать; ошибки изменения задачи не должны мешать отправке сообщения. Пользователи без права редактировать участников не смогут автоматически добавить упомянутого сотрудника.
